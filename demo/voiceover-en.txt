We built Hostless Hui, a rotating savings circle where hosting the application does not automatically give someone access to a release code. Members contribute together. The receiving turn changes by cycle. We separate three powers: operating the platform, approving access, and redeeming a release.

In a conventional application, the operator who controls the server can often change permissions or inspect stored secrets. A login screen does not remove that power. For a savings circle, the question is simple: can the group approve access without trusting one host to control every decision?

This working prototype uses explicitly simulated identities and governance. Bao is the recipient for cycle four. Operator tries opening and is denied. Asking for access creates a pending request, not a grant. Hanh approves once; access is still denied. Tuan's independent approval commits the change. Operator can now read the sample package, but cannot redeem Bao's turn. Only the scheduled recipient can redeem once. TideCloak is the intended cryptographic boundary: signed record policies and ORK-mediated decryption should enforce these rights beyond the application server. Our integration is implemented, but live encryption, decryption and quorum remain to be verified.

The possibility is a group that can share oversight without handing one operator permanent authority. Access rotates, approvals are visible, and renewal or revocation requires review. This prototype models disclosure, not financial custody. Tide's live cryptographic proof is the next acceptance gate.
